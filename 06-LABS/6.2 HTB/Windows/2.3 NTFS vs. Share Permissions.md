# NTFS vs. Share Permissions

## SMB

**Server Message Block (SMB)** is a Windows protocol used to share files, folders, printers, and other resources over a network.

* Commonly used in Windows enterprise environments.
* Usually operates over TCP/445.
* Misconfigured shares can expose sensitive data or allow unauthorized access.

## Share vs. NTFS Permissions

NTFS and Share permissions are **separate permission systems** that can apply to the same shared resource.

| Share Permission | Description                                 |
| ---------------- | ------------------------------------------- |
| `Read`           | View files and folders                      |
| `Change`         | Read, modify, add, and delete files/folders |
| `Full Control`   | Change data and permissions                 |

### NTFS Basic Permissions

| Permission             | Description                                 |
| ---------------------- | ------------------------------------------- |
| `Read`                 | Read file contents                          |
| `Write`                | Create/modify files                         |
| `Read & Execute`       | Read files and execute programs             |
| `List Folder Contents` | View files/folders                          |
| `Modify`               | Read, write, modify, and delete             |
| `Full Control`         | Full access, including changing permissions |

### Key Difference

* **NTFS permissions** apply directly to files/folders on the Windows filesystem.
* **Share permissions** apply when accessing the resource through SMB.
* When accessing a resource over SMB, **both permission sets apply**.
* When accessing files locally or through RDP, Share permissions do not apply.
* NTFS permissions provide more granular control.
* NTFS permissions are normally inherited from parent directories.

## SMB ACLs

Both systems use **ACLs (Access Control Lists)** containing **ACEs (Access Control Entries)**.

ACEs commonly assign permissions to:

* Users
* Groups
* Security principals

## Useful SMB Commands

### Enumerate Shares

```bash
smbclient -L SERVER_IP -U username
```

### Connect to a Share

```bash
smbclient '\\SERVER_IP\ShareName' -U username
```

### Mount an SMB Share

```bash
sudo mount -t cifs -o username=username,password=password //SERVER_IP/ShareName /mnt/share
```

Install CIFS utilities if required:

```bash
sudo apt-get install cifs-utils
```

### Windows — List Shares

```cmd
net share
```

Common administrative shares include:

```text
C$
ADMIN$
IPC$
```

`C$` can provide remote access to the Windows `C:\` drive when the account has appropriate privileges.

## Windows Firewall

Windows Defender Firewall can prevent SMB connections even when credentials and permissions are correct.

Profiles:

* `Public`
* `Private`
* `Domain`

Prefer enabling the required inbound firewall rule rather than disabling the firewall completely.

## Workgroup vs Domain Authentication

* **Workgroup:** authentication uses the local Windows **SAM** database.
* **Domain:** authentication is handled through **Active Directory**.

This distinction matters when determining where user credentials are authenticated.

## Security & Pentesting Notes

When assessing SMB:

1. Enumerate available shares.
2. Identify accessible shares.
3. Check Share permissions.
4. Check NTFS permissions.
5. Look for excessive permissions such as `Everyone: Full Control`.
6. Check administrative shares.
7. Review SMB/firewall configuration.
8. Investigate logs and sessions when performing incident response.

**Key takeaway:**

> Effective access to an SMB-shared resource is determined by the combination of **Share permissions + NTFS permissions**.
