# 📝 Note-Taking Method

HTB Academy is primarily used for structured learning, so I **do not create a separate Markdown file for every module or page**.

Instead:

```text
HTB Module / Section
        ↓
Identify important concepts
        ↓
Understand the concept
        ↓
Write concise notes by topic
        ↓
Practice it
        ↓
Record practical application
```


For example:


```text
HTB Academy
    ↓
Linux Fundamentals
    ↓
Filesystem
Permissions
Processes
Services
    ↓
linux-fundamentals.md
filesystem.md
permissions.md
processes.md
services.md
```


This keeps the repository useful as a long-term reference.



# 🧠 Note Quality Rules

Notes should:

* Be written in my own words
* Focus on understanding
* Include important commands
* Explain security relevance
* Include practical examples where useful
* Link theory to labs/projects
* Avoid unnecessary repetition

### Avoid

* Copying large sections of HTB content
* Recording every command from a module
* Creating notes just to increase file count
* Turning every simple exercise into a full report
