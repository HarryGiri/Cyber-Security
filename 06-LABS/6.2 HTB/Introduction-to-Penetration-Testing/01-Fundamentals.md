# Fundamentals

## What Is Penetration Testing?

Penetration testing is an authorized security assessment in which
testers evaluate systems, applications, networks, or other assets from
an attacker’s perspective.

The goal is not simply to find vulnerabilities, but to determine whether
weaknesses can be safely validated, what impact they could have, and how
they should be remediated.

## Main Activities

A typical penetration test includes:

1.  **Reconnaissance** — collect information about the target.
2.  **Vulnerability Assessment** — identify potential weaknesses.
3.  **Exploitation** — safely validate whether weaknesses are
    exploitable.
4.  **Post-Exploitation** — determine impact and possible attack paths.
5.  **Reporting** — document findings, evidence, impact, and
    remediation.

``` text
Reconnaissance
      ↓

```

## Why Organizations Perform Penetration Tests

Organizations use penetration testing to:

- Identify security weaknesses.
- Validate security controls.
- Test detection and response capabilities.
- Assess real-world impact.
- Prioritize remediation.
- Support compliance and due diligence.
- Improve security awareness.
- Verify patch management.
- Test new technologies.
- Establish a baseline for future security improvements.

### Important Limitation

A penetration test is a point-in-time assessment. A test cannot prove
that an environment is permanently secure because systems,
configurations, applications, and threats change over time.

## Goals of Penetration Testing

### 1. Identify Security Weaknesses

Find vulnerabilities, insecure configurations, exposed services, weak
authentication, and other weaknesses that could be abused.

### 2. Validate Security Controls

Determine whether implemented controls actually reduce risk as intended.

### 3. Test Detection and Response

Assess whether suspicious activity can be detected and whether the
organization can respond appropriately.

### 4. Assess Real-World Impact

Move beyond a vulnerability description and determine what an attacker
could realistically achieve.

### 5. Prioritize Remediation

Use technical findings and business impact to help organizations focus
on the most important fixes.

### 6. Compliance and Due Diligence

Testing can support regulatory, contractual, and security requirements.

### 7. Security Awareness

Realistic findings can demonstrate security weaknesses to technical and
non-technical stakeholders.

### 8. Patch Management

Testing can help verify whether security patches and fixes have
addressed known weaknesses.

### 9. New Technologies

New applications, platforms, and infrastructure can introduce risks that
require security testing.

### 10. Security Improvement Baseline

Results can provide a reference point for measuring future security
improvements.

## Key Takeaway

Penetration testing combines technical testing with security reasoning:

> Find weaknesses → validate them safely → understand impact → document
> evidence → support remediation.
